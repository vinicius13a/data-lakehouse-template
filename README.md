# Data Lakehouse Template

A reusable, **domain-agnostic** template for a dimensional data warehouse built with
**Dataform** on **Google BigQuery**, following a **Medallion Architecture**
(Bronze → Silver → Gold). It ingests CDC data from a relational source (e.g. MySQL /
PostgreSQL CloudSQL) via **Google Cloud Datastream** and transforms it into
analytics-ready fact and dimension tables consumed by **Looker**.

> This repository contains **fictional, generic business data** (Sales, Purchases,
> Customers, Products, Stores, Suppliers). It carries no company-specific tables,
> schemas or business rules. Fork it and replace the sample entities with your own.

## Architecture Overview

```
Relational Source (OLTP: sales_app, procurement)
        |
        v  Google Cloud Datastream (CDC)
+-------------------------------+
|  Data Lake (GCP Project)      |
|  Schemas: sales_app,          |
|           procurement         |
+---------------+---------------+
                |  sources.js
                v
+-------------------------------+
|  Sources Layer                |
|  raw__sales_app,              |  <-- Deduplicated views
|  raw__procurement             |
|  historical__sales_app,       |  <-- Temporal views (valid_from/to)
|  historical__procurement      |
+---------------+---------------+
                |
                v
+-------------------------------+
|  Bronze (bronze_us)           |  <-- Temporal joins, CDC filtering, renaming
+-------------------------------+
|  Silver (silver_us)           |  <-- Business naming, PascalCase views
+-------------------------------+
|  Dynamic (silver_us)          |  <-- SCD Type 2 via FARM_FINGERPRINT
+-------------------------------+
|  Gold (gold_us)               |  <-- Star schema: facts + dimensions
+-------------------------------+
|  Assertions                   |  <-- Data quality checks
+-------------------------------+
        |
        v  LookML
+-------------------------------+
|  Looker (Semantic Layer)      |  <-- views, dashboards, explores
+-------------------------------+
```

## Medallion Layers

| Layer | Schema | Type | Naming Convention | Description |
|---|---|---|---|---|
| **Sources** | `raw__*`, `historical__*` | Auto-generated views | `raw__<schema>.<table>`, `historical__<schema>.<table>` | Generated by `sources.js` from `sources.json`. Raw views deduplicate; historical views add `valid_from`, `valid_to` for temporal analysis via Datastream metadata. |
| **Bronze** | `bronze_us` | `type: "view"` | `brz_<entity>` | First usable layer. Temporal overlap joins between historical tables, minimal transform, lookup enrichment. CDC filtering: DELETE / UPDATE-DELETE records are excluded via `_metadata_change_type`. |
| **Silver** | `silver_us` | `type: "view"` | `DimX`, `FactX` (PascalCase) | Business-named views with clean column aliases. Uses `func_meta_columns.js` helpers for `valid_from` / `valid_to` / `is_valid`. |
| **Dynamic** | `silver_us` | `type: "table"` | `dynamic__DimX`, `dynamic__FactX` | SCD Type 2 engine (`dynamic.js`). `FARM_FINGERPRINT` for change detection: `_meta_fingerprint_type1` (identity/PK hash) and `_meta_fingerprint_type2` (full-row hash = surrogate key). DELETE + MERGE pattern. |
| **Gold** | `gold_us` | `type: "table"` / `"incremental"` | `DimX`, `FactX` | Final star schema. Dimensions read from `dynamic__DimX` excluding fingerprint columns. Facts resolve foreign keys via CTE + `QUALIFY ROW_NUMBER`. Partitioned and clustered. |
| **Assertions** | `dataform_assertions` | `type: "assertion"` | Per-model | Data quality checks (completeness, validity, ranges, referential integrity). |

## Data Models

### Dimensions

| Model | Primary Key | Source | Description |
|---|---|---|---|
| **DimCustomer** | `sk_customer` | `sales_app.customers` | Customer demographics, location, segment. |
| **DimProduct** | `sk_product` | `sales_app.products` | Product catalog: name, category, list price, unit cost. |
| **DimStore** | `sk_store` | `sales_app.stores` | Store / location details: region, type. |
| **DimSupplier** | `sk_supplier` | `procurement.suppliers` | Supplier / vendor details. |
| **DimCalendar** | `sk_date` | Generated (1900-2050) | Calendar dimension; `sk_date` as INT64 in YYYYMMDD format. |

### Facts

| Model | Primary Key | Grain | Type | Description |
|---|---|---|---|---|
| **FactSales** | `sk_sales` | One row per sales order line | Incremental | Sales order lines: quantity, price, discount, gross / net amount, margin. |
| **FactPurchases** | `sk_purchase` | One row per purchase order line | Incremental | Purchase order lines to suppliers: quantity ordered, unit cost, total cost. |

## Key Technical Patterns

### CDC Filtering (DELETE / UPDATE-DELETE)

Datastream CDC events include `_metadata_change_type`. Records representing deleted
states are excluded from the pipeline:

```sql
QUALIFY ROW_NUMBER() OVER (
  PARTITION BY primary_key
  ORDER BY valid_from DESC
) = 1
AND _metadata_change_type NOT IN ('DELETE', 'UPDATE-DELETE')
```

### Temporal Overlap Join

Bronze views join `historical__` tables so that records valid during the same period
are matched:

```sql
FROM historical__sales_app.orders AS o
LEFT JOIN historical__sales_app.order_items AS oi
  ON o.id = oi.order_id
  AND o.valid_from < COALESCE(oi.valid_to, DATETIME("9999-12-31"))
  AND COALESCE(o.valid_to, DATETIME("9999-12-31")) > oi.valid_from
```

### SCD Type 2 via FARM_FINGERPRINT (`dynamic.js`)

1. **`_meta_fingerprint_type1`** = `FARM_FINGERPRINT(PK columns [+ valid_from])` — identifies the entity version.
2. **`_meta_fingerprint_type2`** = `FARM_FINGERPRINT(full row)` — detects any change.
3. **`sk_<entity>`** = `_meta_fingerprint_type1` — surrogate key.

Cycle: `preOps` (CREATE IF NOT EXISTS) → `query` (empty) → `postOps` (DELETE changed + MERGE new/changed + DELETE removed).

### Gold FK Resolution

```sql
WITH customer_sk_resolved AS (
  SELECT fact.sk_sales, dim.sk_customer
  FROM dynamic__FactSales AS fact
  INNER JOIN dynamic__DimCustomer AS dim
    ON fact.customer_id = dim.customer_id
    AND fact.valid_from >= dim.valid_from
  QUALIFY ROW_NUMBER() OVER (
    PARTITION BY fact.sk_sales ORDER BY dim.valid_from DESC
  ) = 1
)
```

### Calendar Foreign Keys

All date foreign keys are stored as `INT64` in `YYYYMMDD` format, matching `DimCalendar.sk_date`:

```sql
CAST(FORMAT_DATE('%Y%m%d', some_date) AS INT64) AS fk_date_event
```

### `is_valid` Field

`is_valid` is a **BOOLEAN** field in all SCD2 tables. Always use `is_valid = true`,
never `is_valid = 'Yes'` or `is_valid = 1`.

## Looker Semantic Layer

LookML files live in `lookML/gold-model/` using the `.txt` extension (project convention).

| Asset | Location |
|---|---|
| Views | `lookML/gold-model/views/*.txt` |
| Dashboards | `lookML/gold-model/dashboard/*.txt` |
| Model | `lookML/gold-model/gold-model.txt` |

## Project Structure

```
definitions/
  _project.js            # Multi-env GCP project mapping
  sources.js             # Auto-generates raw__ and historical__ views
  sources.json           # Source table registry
  data_columns.json      # Shared column descriptions for generated views
  func_meta_columns.js   # Temporal helpers (valid_from/to/is_valid)
  med_bronze/            # Bronze layer views (brz_*)
  med_silver/            # Silver views (DimX/FactX) + dynamic.js
  med_gold/              # Gold tables (star schema)
  assertions/            # Data quality checks
lookML/gold-model/
  gold-model.txt         # Looker model definition
  views/                 # LookML view files (.txt)
  dashboard/             # LookML dashboard files (.txt)
docs-portal/             # MkDocs Material documentation site
  docs/catalogo/         # Data catalog (facts + dimensions)
```

## Getting Started

1. Replace the placeholder GCP project IDs in `definitions/_project.js`.
2. Point `sources.json` at your own source schemas and tables.
3. Adjust the sample Bronze/Silver/Gold models to your domain.
4. Compile: `dataform compile --json`.
